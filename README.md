# Classroom BLE App

课堂场景下的 BLE 文本广播工具。  
一个 App 提供两种工作模式：
- 发送模式（教师手机）
- 接收模式（学生平板）

核心目标：在无网络或弱网络环境下，快速把短文本从教师端发送到学生端进行全屏展示。

## 应用场景（老师-学生一对一）

这个 App 主要用于老师与学生一对一教学场景：
- 学生面前放一台平板作为展示端（接收模式）。
- 老师手持手机作为发送端（发送模式）。
- 老师输入生字或短语后，学生平板立即大字显示，便于学生专注观察和跟读。

没有这个程序时，常见做法是老师先在纸上手写，再把纸拿给学生看。  
这种方式会有几个问题：书写重复、切换慢、展示距离受限。  
使用本 App 后，老师可以直接在手机输入并投送到平板，展示更快、更清晰，也更适合反复练习生字。

## 这个 App 是做什么的

Classroom BLE App 用于课堂中的“短内容同步展示”，例如：
- 汉字听写词语
- 数字与算式
- 拼音或简短提示语
- 课堂口令、抢答题干、签到码

传输方式为 BLE（低功耗蓝牙），不依赖互联网。教师端发一条短文本，学生端收到后立即大字全屏显示，便于全班观看。

## 功能详解

1. 单 App 双角色
- 同一个安装包可以切换为“发送模式”或“接收模式”。
- 发送模式通常运行在教师手机上。
- 接收模式通常运行在学生平板上。

2. 自动发现与绑定
- 首次进入发送模式或首次发送时，系统会自动扫描附近可连接的接收端设备。
- 发现目标平板后自动完成绑定，后续会记忆该设备信息。

3. 自动重连上次设备
- 绑定成功后，后续进入发送模式会优先连接上次绑定的平板，减少重复扫描操作。

4. 可靠发送机制（ACK + 重试）
- 每条消息发送后会等待接收端 ACK（确认回执）。
- 若在超时时间内未收到 ACK，会自动重试，最多 2 次。
- 这样可降低课堂环境下临时干扰导致的丢包。

5. 接收端全屏展示
- 接收端收到文本后会以大字号全屏展示。
- 字号会根据文本长度自动缩放，兼顾可读性与完整显示。

6. 输入边界
- 单条消息长度限制为 1~16 字符。
- 适合短信息快速投送，不面向长段落内容。

## 如何使用

### 环境准备

1. 用 Android Studio 打开项目目录 `XXClass`。
2. 确认 `local.properties` 中 `sdk.dir` 指向本机 Android SDK。
3. 准备两台 Android 设备：
- 一台教师手机（发送端）
- 一台学生平板（接收端）
4. 两台设备均开启蓝牙。

### 首次使用（自动配对）

1. 在平板上启动 App，切换到“接收模式”并保持在前台。
2. 在手机上启动 App，切换到“发送模式”。
3. 系统会在后台自动扫描并绑定平板。
4. 在输入框中输入 1~16 字符内容并发送。
5. 观察平板端是否全屏显示该内容。

### 日常使用（已绑定）

1. 平板进入“接收模式”并保持蓝牙开启。
2. 手机进入“发送模式”，App 会自动预连接并优先连接上次绑定设备。
3. 输入课堂内容并发送。
4. 如果环境干扰导致一次发送失败，系统会自动重试（最多 2 次）。

## 典型课堂流程（建议）

1. 上课前 1 分钟：教师手机和平板都打开 App。
2. 快速确认平板处于接收模式，手机进入发送模式后会自动连接。
3. 课堂中按题目逐条发送短文本。
4. 若需切换到另一台平板，重新安装或清空应用数据后再自动配对。

## 权限与设备要求

- 设备需支持 BLE。
- 接收端设备需支持 BLE 广播（Peripheral）能力。
- Android 12 及以上系统需授予蓝牙相关运行时权限。
- 建议关闭系统省电策略对 App 的限制，避免后台被过早回收影响连接稳定性。

## 常见问题

1. 扫描不到平板
- 确认平板已进入接收模式并停留在前台页面。
- 确认两台设备蓝牙已开启且距离较近。
- 检查系统是否拒绝了蓝牙权限。

2. 发送后偶尔无显示
- 查看发送端是否收到 ACK。
- 若无 ACK，系统会自动重试；可等待重试完成或手动再次发送。
- 尽量避免设备之间有强干扰源或距离过远。

3. 文本显示太小或被截断
- 单条内容建议控制在 16 字符以内（系统上限）。
- 使用更短句子分多次发送可获得更好的展示效果。
